# Voice and Evidence

## Voice Calibration

When the user supplies a writing sample, read it before rewriting. Notice its
sentence length, vocabulary, contractions, formality, humor, point of view,
confidence, punctuation, and paragraph shape. Match those features where they
serve the audience. Do not turn a blunt writer into a polite corporate writer.

Use these voice profiles only as starting points:

* Casual keeps contractions, direct address, uneven rhythm, and ordinary words.
* Professional keeps measured claims, clear structure, and restrained humor.
* Technical keeps exact terms, mechanisms, numbers, code, and explicit limits.
* Warm keeps empathy and personal detail without praise or emotional inflation.
* Blunt keeps short direct claims and names the cost, failure, or disagreement.

## Content Boundaries

Treat writing instructions as instructions, not source text. Do not repeat them
in the revised artifact.

Preserve every source claim unless the user asks for a reduction. When a claim
is unsupported, choose one of three actions:

1. Keep the claim and identify its source.
2. Label it as an opinion, estimate, hypothesis, or placeholder.
3. Ask for the missing evidence or remove the claim.

Never create a more specific fact to replace a vague one. Do not add a person,
date, metric, quote, study, product feature, workflow, promise, or outcome.
Do not make support, recruiting, product, policy, incident, or education copy
promise an action that the source does not promise.

## Format Boundaries

In file mode, preserve YAML frontmatter, code fences, tables used as data,
JSON, shell commands, URLs, link targets, citations, and quoted material.
Change prose around those structures only when the user asks for a broader
change. For a Markdown file, keep reference definitions and heading targets
valid.

## Final Voice Check

Ask whether the revision still sounds like the writer, whether a real detail
was lost, whether a new claim appeared, and whether the rewrite replaced one
formula with another. If the answer to the last two questions is yes, restore
the source or ask the user.
