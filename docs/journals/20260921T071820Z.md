# Revert Gitleaks to the Upstream Hook

Date: 2026-09-21T07:18:20Z

This task supersedes the note in [Journal 20260921T064445Z][journal-064445] and
[Journal 20260921T065845Z][journal-065845] that retained the `gitleaks-system`
hook.

## Reason

The `gitleaks-system` hook ran the `gitleaks` executable from the Nix
environment. The `rev: v8.30.1` field then selected only the hook definition,
not the scanner. Renovate would continue to bump that revision without any
effect on the version that runs. A secret scanner must not carry a pinned
version that does not describe the binary in use.

The hook also needed `pass_filenames: false`, because the upstream system hook
omits that field and pre-commit would otherwise append file names to a command
that accepts one path.

The cache repair in the previous task removed the reason to special case this
hook. The `keep-sorted` and `yamlfmt` hooks use the same `language: golang`
path and now pass.

## Changes

- `.pre-commit-config.yaml`: Restore the `gitleaks` hook.
- `shell.nix`: Remove `gitleaks` from `minimal-shell` and `standard-shell`.

Both files are now identical to their state before this work started.

## Cost

The `gitleaks` hook builds a Go binary on a cache miss. The measured cost of a
comparable Go hook build is about 15 seconds, and it applies only when the
cache key changes.

## Validation

```shell
pre-commit install-hooks
pre-commit run gitleaks --all-files
```

The hook installed and passed.
