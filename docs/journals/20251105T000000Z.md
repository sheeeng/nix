# Configured System-Level Fonts for VS Code and Nerd Fonts

Migrated font management from home-manager user-level to nix-darwin system-level configuration to ensure VS Code can properly access Nerd Fonts. This resolves the issue where VS Code could not find Nerd Font families when installed only at the user level.

## Configuration Changes

1. **Host Configuration** (`hosts/TP95V9LWWL/default.nix`):

   - Expanded `fonts.packages` to include all Nerd Fonts from home-manager configuration
   - Added `roboto-mono` Nerd Font (required for VS Code editor)
   - Added `vt323` font
   - Total of 33 Nerd Font variants now installed system-wide at `/Library/Fonts/Nix Fonts`

2. **VS Code Configuration** (`home-manager/programs/vscode.nix`):
   - Updated `editor.fontFamily` from `"Roboto Nerd Font Mono"` to `"'RobotoMono Nerd Font Mono', 'RobotoMono Nerd Font', monospace"`
   - Updated `terminal.integrated.fontFamily` from `"Monaspace Nerd Font Mono"` to `"'MonaspaceNeon Nerd Font Mono', 'Monaspace Nerd Font Mono', monospace"`
   - Added proper font family name fallbacks for better compatibility

**Font Installation Locations:**

- **User-level** (home-manager): `~/.local/share/fonts` (not reliably accessible by all applications)
- **System-level** (nix-darwin): `/Library/Fonts/Nix Fonts` (accessible system-wide by all applications)

**Font Family Naming:**

- Nerd Fonts installed via Nix use specific family names (e.g., `RobotoMono Nerd Font Mono` not `Roboto Nerd Font Mono`)
- VS Code requires exact font family names or properly configured fallbacks
- Using quoted font names with spaces ensures proper parsing

## Verification Commands

After applying with `darwin-rebuild switch`, verify font installation:

```zsh
# List all Nerd Fonts
ls /Library/Fonts/Nix\ Fonts/

# Verify specific font families
fc-list | grep --ignore-case "nerd font" | grep --ignore-case "roboto\|monaspace"
```
