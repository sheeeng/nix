# Understanding SRI Hash Format in Nix

Documented the modern SRI (Subresource Integrity) hash format that is now the preferred standard in Nix, especially for flakes and modern Nix code.

## SRI Hash Format Structure

The SRI format follows this pattern: `sha256-8NTkPbTfAJkKqhG25vE5WlAFuJ+kldXLQDeEFdQYP5M=`

Components:

- **Algorithm prefix**: `sha256-` (can also be `sha512-`, etc.)
- **Base64-encoded hash**: The cryptographic hash in base64 format
- **Optional padding**: Equals sign at the end

## Comparison with Legacy Format

**Legacy Nix format** (base32):

```nix
sha256 = "14rz33a1b11p835xb5d4kyw0al2s77qyddhim859j06znhyy9m7h";
```

**Modern SRI format** (base64):

```nix
hash = "sha256-8NTkPbTfAJkKqhG25vE5WlAFuJ+kldXLQDeEFdQYP5M=";
```

## Commands to Obtain SRI Hashes

### Method 1: Direct SRI Output with Process Substitution (Recommended)

```bash
nix hash file --sri <(curl --location https://github.com/dj95/zjstatus/releases/download/v0.21.1/zjstatus.wasm)
```

- Uses bash process substitution `<(...)` to stream the download
- `curl -L` downloads the file (following redirects)
- `nix hash file --sri` reads the stream and **directly outputs SRI format**
- Output: `sha256-8NTkPbTfAJkKqhG25vE5WlAFuJ+kldXLQDeEFdQYP5M=`
- No conversion needed

### Method 2: Download First, Then Hash

```bash
curl --location --output zjstatus.wasm https://github.com/dj95/zjstatus/releases/download/v0.21.1/zjstatus.wasm
nix hash file --sri zjstatus.wasm
```

- Downloads file to disk first
- Then hashes it with `--sri` flag
- **Directly outputs SRI format**: `sha256-...`
- Clearer if uncomfortable with process substitution

### Method 3: Legacy Approach (Requires Conversion)

```bash
# Get legacy base32 hash
nix-prefetch-url https://github.com/dj95/zjstatus/releases/download/v0.21.1/zjstatus.wasm
# Output: 14rz33a1b11p835xb5d4kyw0al2s77qyddhim859j06znhyy9m7h

# Convert to SRI format
nix hash to-sri sha256:14rz33a1b11p835xb5d4kyw0al2s77qyddhim859j06znhyy9m7h
# Output: sha256-8NTkPbTfAJkKqhG25vE5WlAFuJ+kldXLQDeEFdQYP5M=
```

### Method 4: Verbose Pipe Method (Educational)

```bash
curl --location https://github.com/dj95/zjstatus/releases/download/v0.21.1/zjstatus.wasm | nix-hash --type sha256 --flat --base32 /dev/stdin
# Output: 14rz33a1b11p835xb5d4kyw0al2s77qyddhim859j06znhyy9m7h (base32)

# Then convert to SRI
nix hash to-sri sha256:14rz33a1b11p835xb5d4kyw0al2s77qyddhim859j06znhyy9m7h
# Output: sha256-8NTkPbTfAJkKqhG25vE5WlAFuJ+kldXLQDeEFdQYP5M=
```

### For Git Repositories (Outputs Both Formats)

```bash
nix-prefetch-git --url https://github.com/isbecker/treefmt-vscode --rev e91d2246e1a1a684ac2065f329ed09fd6cc9dd08
```

Output includes both:

- `sha256`: `14rz33a1b11p835xb5d4kyw0al2s77qyddhim859j06znhyy9m7h` (legacy base32)
- `hash`: `sha256-8NTkPbTfAJkKqhG25vE5WlAFuJ+kldXLQDeEFdQYP5M=` (modern SRI format)

Always use the `hash` field value for modern Nix code.

### Key Differences

| Method | Output Format | Conversion Needed | Best For |
| -------- | --------------- | ------------------- | ---------- |
| `nix hash file --sri` | SRI (`sha256-...`) | No ✓ | Modern Nix, flakes |
| `nix-prefetch-url` | Base32 | Yes | Quick checks, caches file |
| `nix-hash --base32` | Base32 | Yes | Learning, debugging |
| `nix-prefetch-git` | Both formats | No ✓ | Git repositories |

## Hash Format Conversion

```bash
# Convert legacy base32 to SRI
nix hash to-sri sha256:14rz33a1b11p835xb5d4kyw0al2s77qyddhim859j06znhyy9m7h

# Convert SRI to base32 (rarely needed)
nix hash to-base32 sha256-8NTkPbTfAJkKqhG25vE5WlAFuJ+kldXLQDeEFdQYP5M=
```

## Usage in Nix Code

**Modern approach (recommended):**

```nix
fetchurl {
  url = "https://github.com/dj95/zjstatus/releases/download/v0.21.1/zjstatus.wasm";
  hash = "sha256-...";  # SRI format
}
```

**Legacy approach (still supported):**

```nix
fetchurl {
  url = "https://github.com/dj95/zjstatus/releases/download/v0.21.1/zjstatus.wasm";
  sha256 = "...";  # base32 format
}
```

## Why Use SRI Format

- **Modern standard**: Required for Nix flakes and preferred in contemporary Nix code
- **Web standard**: Based on W3C Subresource Integrity specification
- **Explicit algorithm**: The hash algorithm is part of the format, removing ambiguity
- **Consistent**: Works uniformly across different Nix functions and contexts
- **Future-proof**: Aligns with Nix development direction

## Quick Command Reference

| Command | Output Format | Use Case |
| --------- | --------------- | ---------- |
| `nix hash file --sri <file>` | SRI (`sha256-...`) | Direct SRI hash for files |
| `nix-prefetch-url <url>` | Base32 | Quick checks (needs conversion) |
| `nix-prefetch-git --url <url> --rev <rev>` | Both formats | Git repositories |
| `nix hash to-sri sha256:<hash>` | SRI | Convert legacy to SRI |
| `nix hash to-base32 <sri-hash>` | Base32 | Convert SRI to legacy |

**Best Practice**: Use `nix hash file --sri` for files and `nix-prefetch-git` for Git repositories to directly obtain SRI format hashes.
