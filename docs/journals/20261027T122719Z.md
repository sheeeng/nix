# Trust the Cisco Umbrella Root Certificate

Date: 2026-10-27T12:27:19Z.

## Summary

Added the upstream Cisco Umbrella root certificate to the system certificate
bundle on `TP95V9LWWL`. Set `NODE_EXTRA_CA_CERTS` to that bundle for the
primary user.

## Cause

Claude Code `/login` failed with `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Cisco
Umbrella intercepts TLS on this host. The macOS Keychain trusts the Umbrella
root, but the native Claude Code binary and Node.js do not read the Keychain.

The `environment.variables` option of nix-darwin does not reach the Z shell on
this host, because `programs.zsh.enable` is `false`. Use Home Manager session
variables instead.

## Certificate Review

The configuration downloads the certificate with `pkgs.fetchurl` and pins its
hash. The repository does not contain the certificate file. The download URL
needs no authentication. The [Umbrella Root Certificate Guide][umbrella-guide]
tells administrators to download the certificate from the Umbrella dashboard.
Third party deployment documents give the CloudFront URL.

The downloaded certificate and the certificate in the macOS Keychain have the
same SHA-256 fingerprint. Thus, this host uses the generic Cisco root, not a
certificate that is specific to one organization.

The certificate is public data and contains no private key. It contains only
these identity fields:

- Subject and issuer: `O=Cisco, CN=Cisco Umbrella Root CA`.
- Validity: 2016-06-28 to 2036-06-28.
- SHA-256 fingerprint:
  `20:33:7C:06:F7:49:28:7D:52:6D:07:52:C4:29:48:34:21:CE:83:0A:C2:8B:32:2B:84:B1:18:BE:5A:F5:78:7D`.

## Verification

- Evaluated `NODE_EXTRA_CA_CERTS` as `/etc/ssl/certs/ca-certificates.crt`.
- Built the certificate bundle. It contains 119 certificates, including the
  Umbrella root.
