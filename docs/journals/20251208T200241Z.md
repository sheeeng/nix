# Journal Entry: SOPS-NIX Configuration with Passphrase-Protected SSH Keys

**Date:** 2024-12-08T20:02:41Z
**Author:** Leonard Lee
**Host:** TP95V9LWWL
**Topic:** SOPS-NIX Age Key Configuration

## Summary

Configured SOPS-NIX to use dedicated age keys instead of passphrase-protected SSH keys for user-level secret decryption. This resolves potential issues with passphrase prompts during system rebuilds and secret access.

## Problem Statement

The previous configuration used SSH keys (`~/.ssh/id_ed25519`) for SOPS decryption, which can cause issues when:

- SSH keys are protected with passphrases.
- Automated processes need to decrypt secrets without user interaction.
- System rebuilds require secret access during build time.

## Solution Implemented

Modified [home-manager/sops.nix](../../home-manager/sops.nix) to use dedicated age keys instead of SSH keys:

### Configuration Changes

```nix
sops = {
  age = {
    # Use dedicated age key instead of SSH key to avoid passphrase issues.
    # Generate with: age-keygen -o ~/.config/sops/age/keys.txt
    # Get public key with: age-keygen -y ~/.config/sops/age/keys.txt
    # Alternatively, convert SSH key once: ssh-to-age -private-key -i ~/.ssh/id_ed25519 > ~/.config/sops/age/keys.txt
    keyFile = "${homeDirectory}/.config/sops/age/keys.txt";
    # The sshKeyPaths option is commented out to avoid passphrase prompts.
    # Uncomment only if using ssh-agent with loaded keys.
    # sshKeyPaths = [ "${homeDirectory}/.ssh/id_ed25519" ];
  };
  defaultSopsFile = "${sopsFolder}/common.yaml";
  validateSopsFiles = true;
  // ... rest of configuration
};
```

### Key Changes

1. **Removed:** Direct SSH key path reference from `sshKeyPaths`.
2. **Retained:** Age key file path at `~/.config/sops/age/keys.txt`.
3. **Added:** Comprehensive comments documenting the rationale and alternative approaches.

## Architecture Overview

The system now uses a two-tier secret management approach:

### Host-Level Secrets

- **Location:** `/etc/ssh/ssh_host_ed25519_key`.
- **Managed by:** [hosts/darwin/sops.nix](../../hosts/darwin/sops.nix).
- **Purpose:** System-level secrets (GitHub tokens for Nix, host age keys).
- **Key Storage:** `/etc/sops/age/keys.txt` (derived from host SSH key).

### User-Level Secrets

- **Location:** `~/.config/sops/age/keys.txt`.
- **Managed by:** [home-manager/sops.nix](../../home-manager/sops.nix).
- **Purpose:** User-specific secrets (Atuin, SSH keys, API keys, tokens).
- **Key Storage:** Dedicated age key (not derived from SSH).

## Next Steps

To complete the implementation, the following actions are required:

### 1. Generate Age Key

```shell
mkdir --parents ~/.config/sops/age
age-keygen --output ~/.config/sops/age/keys.txt
chmod 600 ~/.config/sops/age/keys.txt
```

### 2. Retrieve Public Key

```shell
age-keygen --yes ~/.config/sops/age/keys.txt
```

Save this public key for the next step.

### 3. Update `.sops.yaml` in Secrets Repository

Add the new age public key to the `.sops.yaml` configuration file in the secrets repository:

```yaml
keys:
    - &user_age_key age1...your_public_key_here...

creation_rules:
    - path_regex: common\.yaml$
      key_groups:
          - age:
                - *user_age_key
```

### 4. Re-Encrypt Secrets

Update all affected secret files with the new key:

```shell
sops updatekeys path/to/common.yaml
```

### 5. Rebuild System

```shell
sudo darwin-rebuild switch --flake ~/github/sheeeng/nix
```

## Alternative Approaches Documented

### Option 1: One-Time SSH-to-Age Conversion

Convert existing SSH key to age format (requires entering passphrase once):

```shell
ssh-to-age --private-key --input ~/.ssh/id_ed25519 > ~/.config/sops/age/keys.txt
```

### Option 2: SSH Agent Integration

Use SSH agent to handle passphrase prompts (requires uncommenting `sshKeyPaths`):

```shell
ssh-add ~/.ssh/id_ed25519
```

Then enable in configuration:

```nix
sshKeyPaths = [ "${homeDirectory}/.ssh/id_ed25519" ];
```

## Benefits

1. **No Passphrase Prompts:** Eliminates interactive prompts during system rebuilds.
2. **Automation-Friendly:** Allows unattended secret decryption.
3. **Security Maintained:** Age keys protected by file permissions (mode 0600).
4. **Clear Separation:** Distinct keys for SSH operations versus secret management.
5. **Documented Alternatives:** Multiple approaches preserved in comments for flexibility.

## Security Considerations

- Age keys are stored unencrypted but protected by file permissions (0600).
- This is equivalent to using SSH keys without passphrases.
- The host-level secrets continue using the system SSH host key for maximum security.
- User-level secrets use the dedicated age key for operational convenience.
