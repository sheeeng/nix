# AKS MCP Kubelogin Fix

**Date:** 2026-02-03T10:14:23Z

## Problem Identified

The AKS MCP server wrapper failed to authenticate to AKS clusters with a "Forbidden" error. The issue was not network filtering but missing `kubelogin` in the Nix package's PATH wrapper.

## Root Cause

The Nix package for `aks-mcp-server` only included `azure-cli` and `kubectl` in its PATH, but not `kubelogin`, which is required for Azure AD authentication to AKS clusters. While `kubelogin` was available in the user PATH (`~/bin/kubelogin`), the sandboxed MCP server couldn't access it.

## Solution Applied

Added a Nix overlay in `overlays/default.nix` that wraps the `aks-mcp-server` binary to include `kubelogin` in its PATH:

```nix
# Add kubelogin to AKS MCP server PATH for Azure AD authentication.
# This allows kubectl to authenticate to AKS clusters using Azure AD.
# @upstream-issue https://github.com/Azure/aks-mcp/issues/TBD
aks-mcp-server = prev.aks-mcp-server.overrideAttrs (old: {
  buildInputs = (old.buildInputs or [ ]) ++ [ final.makeWrapper ];
  postFixup = (old.postFixup or "") + ''
    wrapProgram $out/bin/aks-mcp \
      --prefix PATH : ${final.lib.makeBinPath [ final.kubelogin ]}
  '';
});
```

**Restart OpenCode** for the changes to take effect. The MCP servers are spawned when OpenCode starts, so they need to be restarted to pick up the new package.

This should now work without the "Forbidden" error because kubelogin will be able to authenticate properly using Azure AD credentials.
