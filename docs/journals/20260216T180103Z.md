# Fix Terraform Build Failure on macOS (aarch64-darwin)

**Date:** 2026-02-16T18:01:04Z

## Problem

Build was failing with Terraform 1.14.5 compilation errors on macOS (aarch64-darwin):

```
go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp/internal/semconvutil: open /nix/var/nix/builds/.../go-build.../b783/_pkg_.a: operation not permitted
google.golang.org/api/transport/http/internal/propagation: open /nix/var/nix/builds/.../go-build.../b785/_pkg_.a: operation not permitted
k8s.io/apimachinery/pkg/types: open /nix/var/nix/builds/.../go-build.../b841/_pkg_.a: operation not permitted
```

This is a known issue with building Go packages in Nix on macOS, often related to sandbox permission errors.

## Root Cause

Terraform was being included in `home-manager/packages.nix` for Darwin aarch64 systems (line 323):

```nix
++ (pkgs.lib.optionals (pkgs.stdenv.isDarwin && pkgs.stdenv.hostPlatform.isAarch64) [
  podman
  podman-compose
  terraform  # <- This was causing the build to fail
]
```

The official Terraform binaries are not pre-built in nixpkgs due to restrictive licensing. When building from source, Go compilation fails with sandbox permission errors on macOS.

## Solution

Replaced Terraform with OpenTofu for Darwin aarch64 systems:

```nix
++ (pkgs.lib.optionals (pkgs.stdenv.isDarwin && pkgs.stdenv.hostPlatform.isAarch64) [
  opentofu  # Drop-in replacement for Terraform
  podman
  podman-compose
]
```

## Why OpenTofu?

1. **Already in use**: OpenTofu is already being used as the formatter for Terraform files in `treefmt.nix`:

    ```nix
    terraform = {
      command = "${lib.getExe pkgs.opentofu}";
    ```

2. **Drop-in replacement**: OpenTofu is a fork of Terraform that maintains compatibility with Terraform configurations.

3. **Better licensing**: OpenTofu uses Mozilla Public License 2.0, which allows pre-built binaries to be distributed.

4. **No build issues**: OpenTofu builds successfully on macOS without sandbox permission errors.

## Other Terraform Usage

The following Terraform-related components remain unchanged:

- **VSCode Extension**: `hashicorp.terraform` extension only depends on `terraform-ls` (language server), not the Terraform binary itself.
- **MCP Server**: `terraform-mcp-server` is a separate package that doesn't require the Terraform binary.
- **OpenCode Configuration**: Already configured to use `opentofu` for Terraform files.
- **Helix Configuration**: Terraform support is commented out in `home-manager/programs/helix/languages/terraform.nix`.

## Files Changed

- `home-manager/packages.nix`: Replaced `terraform` with `opentofu` for Darwin aarch64 systems.
