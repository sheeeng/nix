# Fix Gitleaks Pre-Commit Failure

Date: 2026-09-21T06:44:45Z

## Problem

The `gitleaks` hook failed in continuous integration:

```text
[Errno 2] No such file or directory:
'~/.cache/pre-commit/repoduhzglvu/golangenv-system/bin/gitleaks'
```

The upstream `gitleaks` hook uses `language: golang`. Pre-commit builds the
binary into the hook environment and records the environment as installed. The
job restores `~/.cache/pre-commit` with `actions/cache`, which saves the cache
even when the job is canceled or fails. A restored cache that contains the
installed marker but not the binary causes `pre-commit install-hooks` to skip
the rebuild, and the hook then cannot find the executable.

## Changes

- `.pre-commit-config.yaml`: Replace the `gitleaks` hook with the upstream
  `gitleaks-system` hook and set `pass_filenames: false`. The hook now runs the
  `gitleaks` executable from the Nix environment. This matches the existing
  system hook for `nixfmt`.
- `shell.nix`: Add `gitleaks` to `minimal-shell` and `standard-shell`. The
  nixpkgs unstable version is 8.30.1, which matches the pinned hook revision.
- `.github/workflows/run-pre-commit-via-nix.yaml`: Split the cache step into
  `actions/cache/restore` and `actions/cache/save`. The save step runs only
  after the hooks succeed, so a canceled or failed run cannot publish a
  partial environment cache.

## Validation

```shell
pre-commit run --files .pre-commit-config.yaml shell.nix \
    .github/workflows/run-pre-commit-via-nix.yaml
```

All hooks passed, including `gitleaks`, `actionlint`, `yamlfmt`, `keep-sorted`,
and `nixfmt`.

## Notes

The `run-pre-commit-via-determinate.yaml` workflow has no pre-commit cache
step, so it needed no change. It uses the same `minimal-shell`, which now
provides `gitleaks`.
