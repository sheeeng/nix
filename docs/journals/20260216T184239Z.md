# Understanding Nixpkgs Version Differences: `<nixpkgs>` vs. `nixpkgs#` vs. Flake Inputs

**Date:** 2026-02-16T18:42:39Z  
**Topic:** Nix expression evaluation, nixpkgs sources, version discrepancies  
**Status:** Resolved

## Context

While testing the OpenTofu installation after fixing the Terraform build failure, we discovered that different methods of accessing nixpkgs returned different package versions:

- `nix repl --expr 'import <nixpkgs> {}'` returned OpenTofu 1.11.4
- `nix eval nixpkgs#opentofu` returned OpenTofu 1.11.5
- System installation showed OpenTofu 1.11.5

This raised the question: why do these supposedly identical nixpkgs references return different versions?

## Investigation

### Checking Nixpkgs Sources

We examined three different ways nixpkgs is resolved:

1. **Channel-style `<nixpkgs>` path:**

    ```bash
    nix-instantiate --eval --expr 'builtins.nixPath'
    # Result: flake:https://flakehub.com/f/DeterminateSystems/nixpkgs-weekly/*.tar.gz
    ```

2. **Flake registry `nixpkgs#`:**

    ```bash
    nix registry list | grep "^global flake:nixpkgs"
    # Result: github:NixOS/nixpkgs/nixpkgs-unstable

    nix flake metadata nixpkgs
    # Revision: ac055f38c798b0d87695240c7b761b82fc7e5bc2
    # Last modified: 2026-02-15 18:45:47
    ```

3. **System flake input:**
   The system uses the nixpkgs input pinned in `flake.lock`, which points to the same nixpkgs-unstable as the registry.

## Root Cause

The version difference exists because **`<nixpkgs>` and `nixpkgs#` resolve to different nixpkgs sources:**

| Source       | Resolves To                                        | OpenTofu Version | Update Frequency                |
| ------------ | -------------------------------------------------- | ---------------- | ------------------------------- |
| `<nixpkgs>`  | [FlakeHub nixpkgs-weekly][flakehub-nixpkgs-weekly] | 1.11.4           | Weekly snapshots                |
| `nixpkgs#`   | [GitHub nixpkgs-unstable][nixpkgs-unstable]        | 1.11.5           | Continuous updates              |
| System flake | Pinned in `flake.lock`                             | 1.11.5           | When running `nix flake update` |

### FlakeHub nixpkgs-weekly

The `<nixpkgs>` path resolves to:

```
flake:https://flakehub.com/f/DeterminateSystems/nixpkgs-weekly/*.tar.gz
```

This is a **curated weekly snapshot** of nixpkgs provided by [DeterminateSystems][determinate-systems] through FlakeHub. It's designed to provide more stable, tested package sets updated on a weekly cadence rather than continuous updates.

### GitHub nixpkgs-unstable

The flake registry entry for `nixpkgs` points to:

```
github:NixOS/nixpkgs/nixpkgs-unstable
```

This is the **official nixpkgs-unstable branch** from the NixOS GitHub repository, which receives continuous updates as packages are merged.

## Implications

### For Reproducibility

This demonstrates an important principle in Nix: **the source matters for reproducibility**.

- Using `import <nixpkgs> {}` depends on the system's `NIX_PATH` configuration, which can vary between systems
- Using flake inputs (pinned in `flake.lock`) provides reproducibility across systems
- Using flake registry references (`nixpkgs#`) provides consistency but tracks the latest unstable

### For REPL Usage

When testing packages in `nix repl`, you must be aware which nixpkgs you're loading:

**To match your system's packages:**

```bash
nix repl
:lf .#
inputs.nixpkgs.legacyPackages.aarch64-darwin.opentofu
```

**To use nixpkgs-unstable (flake registry):**

```bash
nix repl
:lf nixpkgs
lib.getExe' pkgs.opentofu "tofu"
```

**To use nixpkgs-weekly (channel-style):**

```bash
nix repl --expr 'import <nixpkgs> {}' --impure
```

## One-Liner REPL Evaluation

We also explored how to evaluate Nix expressions using `nix repl` in a single command without interactive input:

**Single expression:**

```bash
nix repl --expr 'import <nixpkgs> {}' --impure <<< 'lib.getExe'\'' pkgs.opentofu "tofu"'
```

**Multiple expressions:**

```bash
nix repl --expr 'import <nixpkgs> {}' --impure <<EOF
lib.getExe' pkgs.opentofu "tofu"
pkgs.opentofu.version
builtins.readDir "\${pkgs.opentofu}/bin"
EOF
```

**Alternative using echo:**

```bash
echo 'lib.getExe'\'' pkgs.opentofu "tofu"' | nix repl --expr 'import <nixpkgs> {}' --impure
```

These commands pipe expressions into the REPL, which evaluates them and exits, providing non-interactive evaluation suitable for scripting.

## Best Practices

1. **In flakes:** Always use explicit inputs rather than `<nixpkgs>` for reproducibility
2. **In REPL testing:** Use `:lf .#` to load your flake's exact nixpkgs version
3. **For scripts:** Use `nix eval` with explicit flake references rather than channel-style paths
4. **For systems:** Pin nixpkgs in `flake.lock` and update intentionally with `nix flake update`
