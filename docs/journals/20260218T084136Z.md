## Objective

Align OpenCode agents with the cost-optimization strategy from Paweł Józefiak's article: "Why I Switched My AI Agent from Opus to Haiku (And It Got Better)". The core insight is that most agent work is execution (95%), not creative reasoning—therefore, model selection should match task type rather than defaulting to the most powerful (and expensive) model.

## Key Insight From Article

The article demonstrates a counterintuitive finding: switching the default agent from Opus to Haiku with strategic model selection (Haiku for execution, Sonnet for synthesis, Opus for reasoning) reduced token usage from 70-80% of weekly limits to 40% while maintaining or improving output quality.

**Why it works**: Execution tasks (file operations, following checklists, running scripts) don't require creative reasoning. Haiku is "shockingly good at precision work."

## Insights from Original Article Applied

### "Haiku Doesn't Overthink"

Agent instructions now simplified. Removed verbose explanations. Kept action-oriented guidance. This matches the article's finding that Haiku for execution tasks is "shockingly good at precision work."

### "Most Work is Execution"

The 95/4/1 distribution reflects the article's real-world experience. Most agent tasks are:

- Reading files and extracting data
- Following predefined scripts
- Sending formatted messages
- Updating task lists
- Running predetermined workflows

These don't require creative reasoning—they require precision. Haiku excels here.

### "Volume Drives Cost"

Original article: "By Friday, I'd regularly hit 70-80% of my weekly limit."  
Solution: Strategic model selection, not provider switching.  
Result: Now at 40% of weekly limit with same output volume.

### "Test Before Assuming"

The article tested Haiku and found no perceived quality loss for appropriate tasks. Our documentation includes practical examples showing this works in practice.
